### What to build

1. `fakes/WheelPlant.{h,cpp}` with a fidelity header:
   - Model (plan 6.2): J theta'' = tau - b theta' - F_c sign(theta') (+ optional hands-on spring k and damper c towards a hand position), tau = torque from the chip. Parameters in SI units with the plan's nominal ranges documented (J 0.005-0.08 kg m^2, b 0.0005-0.05 N m s/rad, F_c 0-0.2 N m, full-scale torque 5-25 N m for 32767 torque counts, optional first-order current-loop lag, default ideal); no default hides a choice: a test sets its parameters or uses a named nominal set defined in the header with its source (plan 6.3).
   - **Integration per step: exact for the linear part.** Over one step dt the torque is held (zero-order hold); without Coulomb friction the step uses the exact solution of the linear ODE (omega and theta in closed form, b = 0 included), so energy and decay are exact up to floating point. Coulomb friction: a documented stick / slip rule (sticks while |tau| <= F_c at omega = 0; while moving, the friction torque is constant over the step and the step is split at a zero crossing of omega, so it never reverses through zero by friction alone). Double precision.
   - **Effective torque (audit A, G1):** the plant reads, from the fake chip at each step: torque target 0x64 [31:16] (s16), and applies it only when the motion mode 0x63 [7:0] is torque mode (1), the PWM mode 0x1A [7:0] is FOC (7) and ENABLE_IN (0x76 bit 15, the fake's model of ENI) is high, clamped to the torque limit of 0x5E (look up which bits hold the torque limit and cite the datasheet page); otherwise tau = 0. Each condition with its datasheet citation.
   - **Position out (audit A, G2):** 0x6B is a signed 32-bit PhiM count, 65536 per mechanical revolution (datasheet page). The plant keeps its own continuous angle and advances 0x6B by the change in whole counts each step (carrying the fractional remainder, int32 wrap-around), so a firmware write to 0x6B (zeroing) rebases the count instead of being overwritten (use the fake's `onWrite(0x6B)`). Optional velocity / other registers only if the firmware reads them on the F1 path (check, cite).
   - Attach / detach to `FakeTmc4671`, `step(dt)` called by `ChainScheduler` step (f) once per simulated ms (wire it in `ChainScheduler` / `IntegrationFixture`: an `attachPlant(...)` helper), observers for theta, omega, tau applied, energy.
2. `support/OscillationDetector.{h,cpp}`: from a sampled signal (fixed sample period) after an excitation: dominant frequency (from zero crossings or peaks, method documented), the cycle-to-cycle amplitude ratio (per full cycle, from successive same-sign peaks), and a classification `decaying` / `sustained` / `growing` with parameters `eps` and the minimum number of cycles (plan 6.3: sustained = ratio within 1 +- eps for >= 10 cycles above a quantisation floor; growing = ratio > 1 + eps), plus `insufficient` when there are too few cycles above the floor. Strict and documented.
3. `support/FrequencyResponse.{h,cpp}`: gain and phase of an output sequence relative to a sinusoidal input at a known frequency by single-bin DFT over a whole number of periods (plan 6.3 step 2); reports an error when the window is not a whole number of periods or too short. Phase convention documented (output lagging = negative).
