## Rules common to all I2 work orders

The ten "Rules common to all I1 work orders" (`I1_WORK_ORDERS.md`) apply unchanged (reports from the parsed descriptor, settings only through the real commands, observation at the chip, oracles, steady-state rule, defaults visible, markers, bring-up and `IT_DELETES_FFBHIDMAIN`, both builds, names). In addition:

1. **Next free numbers**: IB 38, INR 33, IQ 14. Writers use provisional labels `IB I2-<n>/<k>` / `INR I2-<n>/<k>`; the lead renumbers before each commit so the registers have no gaps.
2. **Coverage bugs already known on these paths** (search `Tests/Code_Coverage/claude/reports/BUG_REPORT.md` first, cite as "same as bug n"): 33 (slew jump after E-stop), 39 / 40 (E-stop paths), 42 (`tud_suspend_cb` without the `bool` parameter never called), 152 (bus reset gives no unmount; supply loss), 163 (ENABLE_IN stop), 164 (over-temperature). Integration bugs already registered are cited by number: IB 17 (flash-restored `power` never reaches 0x5E for a driver created later), IB 22 (restart after out-of-bounds), IB 24 (start request lost while waiting for power), IB 25 (supply dropout).
3. **Not duplicating I1**: the late-readiness cases of `test_f1_axis.cpp` (LateFixture: constant force set before Running, slew bound after Running, IB 24, IB 25, IB 22) stay; I2 cases cite them by name and add only what they do not prove.
4. **Thread interleaving**: the host scheduler is cooperative (no preemption, plan section 7). A case that claims "not interrupted / not interleaved" says exactly which interleaving it forces (a hook on a chip register write or read that runs a command mid-step) and states that a true preemptive race is a limit.
5. **Waiting for slow loops**: the TMC thread checks ENABLE_IN, temperature and the supply at its own periods (`TMC4671.cpp:553-574`, `:643-650`, `:473-492`); cases advance simulated time by the period stated from those lines, never by a value tuned to make the test pass.
6. **Recovery behaviour**: where the firmware's recovery after a stop is not specified anywhere but the firmware (E-stop release, power return, temperature drop), the "torque returns" part is `characterization:` with an INR, and "no jump beyond the slew limit" is a plain test only if the slew limit is a user setting the case sets.

## Order and parallelism (owner's rules of 2026-11-19 and 2026-11-23)

* **I2-1 first and alone**: every other WO uses its helpers, so it is finished, reviewed, fixed and committed before any writer starts.
* **Then I2-2, I2-3, I2-4 and I2-6 in parallel** (four writers, four different case files, no support edits: a writer that needs a support change stops and reports). Their reviewers run as each writer finishes, within the limit of four agents at once.
* **I2-5 after one of those four is committed** (it is P2 and may need a lead decision on the TIM3 fake; it never runs as a fifth agent).
* **I2-7** after all six are committed. No work of phase I3 starts before the owner approves I2.

## Scope notes and decisions taken in this draft (for the owner)

* **New test files per subject**: `test_f1_driver.cpp` (T1, T2), `test_f1_safety.cpp` (T3-T5), `test_f1_runtime.cpp` (T6-T8), `test_f1_encoder.cpp` (T9), `test_f1_persistence.cpp` (P1, P2). The CMake glob picks them up; no CMake change.
* **No shared-fake edits expected.** All the fake APIs I2 needs exist (`FakeTmc4671::log / onWrite / onRead / setEnableIn / setAdcRaw`, `HostTarget::setPin / triggerExti / outputPin / spiFailNextBlocking`, `HostDcd::suspend / resume / detach / attach`, the TIM3 encoder fake). The only missing piece is a timestamped GPIO log, solved in integration support by sampling the enable pin inside the chip write hook (I2-1 item 3). If a writer finds a defect in a shared fake, it stops; the fix goes through the override (audit, list of changed coverage results, owner approval, `APPROVED_SHARED_EDITS.txt`).
* **Reboot model**: the in-memory flash map survives, everything else is rebuilt through the real `cppmain` (as a power cycle does). `eeprom.c` on NOR flash is not part of this chain (covered by `ffb_flash_tests`, plan section 7).
* **Over-temperature (F1-T5)**: temperature checking is off by default (`TMC4671.h:103`) and only a hardware-version setting turns it on; if no command reaches it, the part is recorded as not reachable by the user's path instead of being forced through a private call.
* **P2 requirements (T7, T8, T9)** are planned as tests, not reasoned out.
* **Already known defects expected to show up**: IB 17 (F1-T1 / F1-P2), bug 42 (F1-T7), bug 33 (F1-T3 release); they are cited, not re-numbered.
