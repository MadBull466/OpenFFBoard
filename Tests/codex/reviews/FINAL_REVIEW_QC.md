## P9 permanent finite-output regression acceptance

Reviewed both bodies/helpers in `Firmware/Tests/codex/cases_target/test_dsp_finite_outputs.cpp`, the writer's report, wrapper source, commands and XML. The sine/cosine test uses finite small inputs, checks each returned sample before comparison, and compares the same float input against host double trigonometry. The supplied CMSIS implementation performs linear interpolation; `(2π/512)²/8` is approximately `1.8825e-5`, below the stated `2.1e-5` tolerance with room for small-input float rounding. This is an accuracy bound for the specified portable path and interval, not a target execution result.

The biquad oracle is independently written as the DF1 equation. Its denominator roots are `0.5` and `-0.25`; absolute feedback sum `0.375` and feedforward sum `0.6875` imply the stated bounded-output estimate `1.1` for unit-bounded input and zero history. The nonzero asymmetric dyadic sequence spans two consecutive 13-sample blocks while the independent double history continues across their boundary. The fixture owns fresh state. Neither production coefficients nor observed production output supplies the expected sequence. Per-sample `isfinite` plus direct error checks avoid the original maximum-reduction defect; NaN or infinity in these output samples cannot disappear from the oracle.

I independently reran the new suite alone: control has two ordinary passes; the sine NaN wrapper yields one ordinary failure first at `std::isfinite(sine)` while the biquad case passes; the biquad NaN wrapper yields one ordinary failure first at `std::isfinite(output[i])` while trigonometry passes.
