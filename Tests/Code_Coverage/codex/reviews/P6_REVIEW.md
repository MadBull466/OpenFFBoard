## Independent checks and assertion strength

- Local counts use signed displacement from centre 32767. Starting there, +32773 crosses a 65536-count period once and leaves hardware count 4, so adding a full period restores position +32773. The symmetric negative case leaves count 65530 and position −32773. The shorter-period and wrong-timer tests distinguish a hard-coded 65536 or unfiltered callback implementation. Index tests establish nonzero position before rejection and then exercise a valid falling edge.
- SSI generator independently XORs odd/even position bit groups to odd parity. Good frame 0x2100 establishes centred position 0x100 before corrupt 0x3000. Both-check-bit rejection and the one-check-bit known issue observe retained position and error count; the latter is not accepted as ordinary success. Forward/backward wrap vectors differ by 32 counts across the turn boundary. Raw-mode defect detection compares two asymmetric frames differing by one count, rather than asserting the current defective absolute value.
- BiSS generator shifts an explicit bitstream and computes polynomial x^6+x+1 by bitwise feedback independently of the table-driven firmware. The bad-CRC case first establishes 0x1000, then delivers a different 0x2000 with one CRC bit flipped and checks both error count and retained state. Separate cases flip data after generating its CRC and cover multiple idle/ack lengths. “No answer” deliberately reaches known clz(0) UB and was not executed here.
- MT6825 generator counts parity bit by bit rather than using firmware XOR folding. Separate upper- and lower-group corruption vectors start with nonzero accepted position 0x100, then offer 0x200; the lower-group bypass mutant below is rejected by both observations. MT6835 uses a bitwise CRC8 over three explicit bytes and has a wrong-CRC retained-state case. Its flipped-status-bit case checks error count only; the more general wrong-CRC case separately observes retained position.
- Full-turn arithmetic uses explicit CPR=262144/2097152/4194304 constants and nonzero wrap endpoints. BiSS/MT tests also distinguish large first-angle behavior as characterization or stated stored-offset behavior. Status flags currently accepted by the firmware are named characterizations, not promoted to verified safe policy.
- SPI callbacks check sequences with port and CS state, two devices with different bytes 0x11/0x22 and distinct CS pins, and two simultaneous hardware ports. I2C callback tests compare a distinct fake handle and preserve the expected own completion. Its second-device wait case separately checks recipient counts; a successful second transfer alone would miss bug89. All these observations occur under serialized fake scheduling, not interrupt preemption.
- Generic CRC table oracles cover all 256 entries (8/16 bit) and all 64 entries (6 bit), with independent bitwise division. Standard named check constants in existing comments are supplemental; their arithmetic is also constrained by direct polynomial/table tests. A zero residual after appending the implementation's own CRC is a consistency property, and is not the sole oracle.

- Remaining command/register/flash bodies listed as deferred need a later body audit for full phase sign-off. Executing them does not replace inspecting their oracles. In particular no full independent MT register-command oracle was derived without its supplied datasheet.
- Existing SPI failed-start known-issue descriptions require HAL recovery for a subsequent transfer, but the sampled release cases at lines 617–665 assert CS/semaphore release without actually retrying. They establish release; a later recovery regression should also drive a second valid transfer and delivered bytes. This is a documented assertion-scope limit, not a reproduced surviving mutant or new firmware finding.
- The BiSS timeout test checks completion after reactivating the finite wait. It relies on fake RTOS timeout semantics; it does not independently assert an exact elapsed simulated deadline in that case. This review does not certify kernel timing or sensor response timing.
- No sanitizer, random-order, whole-target rerun or full mutation sweep was repeated here. Coordinator gate/random-order evidence remains separately attributed. No physical sensor, actual SPI/I2C electrical timing, ISR preemption, hardware DMA lifetime, ARM code path or target integer-shift behavior was verified.
