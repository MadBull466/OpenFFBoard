## What each review must establish

Identify the requirement, public stimulus, initial state, independently derived expected observation, exact asserting case and location, and a plausible incorrect implementation that the assertion distinguishes. For a rejection or no-op, show that the stimulus reached the relevant boundary, that the prior value differs from the incorrect output, and which layer rejected it. State whether an oracle is from a supplied specification, a mathematical or functional invariant, a stated product policy, or current firmware behavior. Preserve open policy questions as characterizations.

Record which files/cases/requirements were assessed and which were sampled, skipped or deferred. For executed evidence record the binary/variant, exact filter (verify the matched case count), observed result and any expected-failure assertion location. For mutants record the scratch change, unmutated control, affected case, outcome and scope of the run. Distinguish a kill by the named case, a kill elsewhere, a surviving mutant, equivalent behavior, and an unexecuted prediction. Whole-suite expected failure can hide a second, unrelated failure. Inspect the assertion itself and record any fixture/setup error. Where relevant use an isolated run and a different order to test shared state. Historical percentages and green cases do not establish test effectiveness independently.

## Lead observations for independent confirmation

- **LEAD-O14 · ODrive request framing.** The supplied 0.5.6 PDF's CAN Messages table marks 0x009 with the call/response asterisk. For 0x017 the table marks the sender with the three-asterisk either-axis footnote; the message name lacks the call/response mark. The accompanying CSV agrees. Neither entry supplies the required request DLC. O14 tests in `Firmware/Tests/Code_Coverage/claude/cases/driver/test_odrive_frames.cpp:470–511` assert DLC 0 and RTR for both. `Firmware/Tests/Code_Coverage/fakes/FakeOdrivePeer.cpp:396–425` rejects a mismatch, while charter L11 calls the request DLC an assumption. A future change in unspecified framing can fail ordinary tests. Separate the verified 0x009 RTR and documented IDs/response layouts from the assumed DLC and 0x017 RTR. Obtain another owner-supplied reference if those fields must become normative.
- **LEAD-O14b · ODrive assertion scope.** The case at `test_odrive_frames.cpp:493–503` claims the peer answers with the same ID but inspects only request counters and the absence of violations. `FakeOdrivePeer.cpp:444–453,472–480` separates response emission from counting received requests. Check whether other tests observe both return frames and correct payloads. This is a local assertion gap, with whole-suite impact still to establish.
- **TMC timing boundary.** R5 uses SPI prescaler and whether the address byte is a separate transfer as a documented proxy. Rev 2.07 §4.2.1 p19 requires an elapsed pause of at least 500 ns for fast reads. A split alone cannot verify pause duration. Report linked host configuration/proxy observations separately from on-wire timing. No firmware defect independently established by this observation.
- **Owner/spec boundaries.** USB HID PID 1.01 remains optional and unsupplied. TMC older/undocumented registers, engineering sample revision, startup CS electrical state and biquad enable behavior on hardware remain open. ODrive enum numbers, 0.5.4 comparison and calibration policy remain open. VESC 7.01 layout supports a 7.01 check; 5.3 pairing layout and unsolicited STATUS liveness remain open. Scripted plants, fake kernel timing/interrupts and real bus timing require separate target evidence. These limits do not block claims with an independent host oracle.
