Filter-specific requirements on top of C1-C6:
- **Init (C3/C4):** after `arm_*_init_*` the instance fields (numStages / numTaps, pCoeffs, pState, postShift, decimation factor M, interpolation factor L ...) hold the arguments; the state buffer is zeroed (fill it with a poison pattern first so a missing clear is visible); documented argument errors (e.g. `arm_fir_decimate_init_*` returns `ARM_MATH_LENGTH_ERROR` when numTaps is not a multiple of M or blockSize is not a multiple of M; interpolate init when numTaps is not a multiple of L): quote the DOC sentence and test the return code and that the instance is not modified on error where DOC says so (else `characterization:`). The state buffer length formulas from the DOC (e.g. numTaps + blockSize - 1, 4 * numStages, numStages * 2 ...) are tested with a GuardedBuffer of EXACTLY that size (sanitizer builds catch overruns): no slack.
- **State continuity (C4):** processing one long block equals processing it in several consecutive blocks (sizes incl. 1, 2, 3, 4, 5, 7 and ones that are not multiples of the unroll factor or of M / L), for every stateful function; two instances are independent; re-init resets the state.
- **DEF (C3):** the difference equation in double (direct form I / II transposed for biquads with ARM's sign convention for a1, a2 (read the DOC), FIR convolution, polyphase decimation / interpolation (output sample counts blockSize/M and blockSize*L)); impulse response and step response with hand-derivable values; for q types derive the scaling (postShift, Q format of the coefficients, accumulator width, saturation) in a comment and test the saturation boundary, not only typical data; one-sided floor error where the code truncates.
- **Sweeps (V41/V42/V50 lesson):** q7 / q15 single-tap or two-tap filters can be swept exhaustively over the input range against the DEF; for wider types use a strided full-range sweep; test numStages / numTaps from 1 up to at least 9 (loop-unroll tails: the FIR / biquad kernels unroll by 4 / 2).
- **Stability of the DEF:** choose coefficients so that the double DEF itself is well conditioned (stable biquads; bounds derived from the sum of |h[n]| for FIR) so bounds are meaningful; derive float bounds per tap or per stage (n * eps * sum|terms|), do not use a magic number.
- Known pitfalls: left shifts of negative values, signed overflow in accumulators, `numTaps` below the unroll size; report UB with file:line (UBSan under `--no-skip`), `KNOWN_ISSUE_UB(_HIDDEN)` per the rules.
