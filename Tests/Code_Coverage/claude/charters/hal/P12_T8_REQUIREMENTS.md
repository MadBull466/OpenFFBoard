## Compiled code and instances

`stm32f4xx_hal_pcd.c`, `stm32f4xx_hal_pcd_ex.c`, `stm32f4xx_ll_usb.c`, with `USB_OTG_FS` as the only instance the tests use (`IS_PCD_ALL_INSTANCE` also accepts `USB_OTG_HS`: no model, not tested). `HAL_PCD_MODULE_ENABLED` is on, `HAL_HCD_MODULE_ENABLED` is off: the host half of `stm32f4xx_ll_usb.c` (`USB_HostInit`, `USB_InitFSLSPClkSel`, `USB_ResetPort`, `USB_DriveVbus`, `USB_GetHostSpeed`, `USB_GetCurrentFrame`, `USB_HC_*`, `USB_DoPing`, `USB_StopHost`, `USB_ReadChInterrupts`) is compiled but only HCD calls it: NOT tested (the owner's scope decision); it is reported as uncovered by design. `USE_HAL_PCD_REGISTER_CALLBACKS` is 0: the register / unregister callback functions are compiled out and the weak callbacks are replaced by the strong ones of `OtgTestSupport.h` (never define a HAL_PCD_* / HAL_PCDEx_* callback in a test file). The HS-only code (`USB_OTG_HS` branches, `DEACHMSK`, DMA mode, `use_dedicated_ep1`) is reachable only by setting those Init fields: DMA mode (`dma_enable`) needs DMA address registers the FS core has not (model: counted as `hostOtgHsOnlyAccesses`); do not test DMA mode, report it. Target facts: the firmware (main.c MX_USB_OTG_FS_PCD_Init) uses 4 endpoints, `PCD_SPEED_FULL`, `PCD_PHY_EMBEDDED`, no DMA, no SOF, no low power, no LPM, VBUS sensing on, no dedicated EP1; `OtgFixture::setFirmwareInit()` sets exactly that.

## Platform (lead): `HalOtg` model

Read the header comment of `HalOtg.h`: registers (masks, rc_w1, derived bits), GRSTCTL completion by poll reads (`hostOtgSetPollReads`: default completes at the first read; 0 never, to test the timeouts), the receive FIFO with status entries and the four TxFIFOs, the host side (`hostOtgHostSetup / HostOut / HostIn`, `UsbReset`, `EnumDone`, `Suspend`, `Resume`, `Sof`, `Vbus`, `DisconnectEvent`), `hostOtgIrqPending`, counters. The model is strict about FIFO overflow / underflow (bus fault that fails the test: `hostOtgStrictFifo(0)` turns it into a counter). Reserved offsets are counted (`hostOtgReservedAccesses`, expect 0 in a normal flow); accesses to registers that exist only on the OTG_HS core but that the generic HAL touches are counted apart (`hostOtgHsOnlyAccesses`: `USB_DevInit` clears DIEPTXF[0..14] (0x104-0x13C) although the FS core has three; `HAL_PCD_EP_Receive` etc. read GSNPSID at 0x40; `USB_DeactivateEndpoint` writes DEACHMSK at 0x83C (0x838 is DEACHINT); `HAL_PCDEx_ActivateLPM` writes GLPMCFG at 0x54). These are model decisions (NEEDS REVIEW 345-346 below), not defects.
Model decisions RM0090 leaves open (state them if a case depends on them): XFRC (OUT) and STUP are set when the matching "transfer completed" / "SETUP completed" status entry is popped from GRXSTSP; the OUT endpoint sets NAKSTS at a completed transfer and at SETUP; the DAINT bit of an IN endpoint is DIEPINT & (DIEPMSK | TXFE when its DIEPEMPMSK bit is set); EPDIS takes effect at once (EPENA clears, EPDISD is set); SNAK sets NAKSTS and INEPNE at once; the USB reset does not change any register by itself; the host helpers do not check the device address.
The HAL calls `HAL_PCD_ResetCallback` from the ENUMDNE branch, not from USBRST. Time: `HAL_Delay` / `HAL_GetTick` advance one tick per call (the model needs no time).

## Requirement groups (one writer, one file each)

### PI (`test_hal_pcd_init.cpp`): initialization, start / stop, core control
`HAL_PCD_Init / DeInit / Start / Stop / DevConnect / DevDisconnect / SetAddress / GetState / SetTestMode / ActivateRemoteWakeup / DeActivateRemoteWakeup / WKUP_IRQHandler`, `HAL_PCDEx_SetRxFiFo / SetTxFiFo / ActivateLPM / DeActivateLPM / ActivateBCD / DeActivateBCD / BCD_VBUSDetect`; LL `USB_CoreReset, USB_CoreInit, USB_SetCurrentMode, USB_GetMode, USB_DevInit, USB_SetDevSpeed, USB_GetDevSpeed, USB_EnableGlobalInt, USB_DisableGlobalInt, USB_SetTurnaroundTime, USB_DevConnect, USB_DevDisconnect, USB_StopDevice, USB_SetDevAddress, USB_ActivateRemoteWakeup, USB_DeActivateRemoteWakeup`.
- PI1 `HAL_PCD_Init`: NULL handle -> HAL_ERROR; state RESET -> MspInit called, Lock unlocked, state BUSY then READY; the register state after init against RM0090 34.17.3 (GAHBCFG, GUSBCFG PHYSEL / FDMOD, GCCFG VBUSBSEN / NOVBUSSENS from `vbus_sensing_enable`, GINTMSK unmasked bits per Init flags (SOF, VBUS), DCFG DSPD, DCTL SDIS set (soft disconnect), FIFO registers zero), all Init variants of the firmware-relevant fields (`vbus_sensing_enable`, `Sof_enable`, `speed`, `dev_endpoints` 1..4, `phy_itface`), the endpoint arrays initialised (IN_ep / OUT_ep num, is_in, maxpacket, xfer_len), state when a LL step fails (poll timeouts: `hostOtgSetPollReads(0)` for CSRST, with the HAL_TIMEOUT -> HAL_ERROR mapping), `HAL_PCD_DeInit` (state, MspDeInit, `USB_StopDevice` effects, returns).
- PI2 `HAL_PCD_Start / Stop / DevConnect / DevDisconnect / SetAddress`: GAHBCFG.GINT, DCTL.SDIS clear / set with the HAL's delay (tick advance), `__HAL_LOCK` handling (a locked handle -> HAL_BUSY), DCFG.DAD, `USB_Address` copy, return values, interrupt mask effects of Stop (`USB_DisableGlobalInt`, `USB_StopDevice`: endpoint registers and FIFO flush per RM0090 34.17.5).
- PI3 `HAL_PCDEx_SetRxFiFo / SetTxFiFo`: GRXFSIZ, DIEPTXF0 / DIEPTXFx start addresses and depths computed from the previous FIFOs (RM0090 34.13.1 FIFO RAM allocation: start address = end of the previous FIFO), the depth limits, `HAL_OK` returns, the fifo number 0 vs 1..3. LPM / BCD (CORRECTION after the T8 survey: `HAL_PCDEx_ActivateLPM / DeActivateLPM / ActivateBCD / DeActivateBCD / BCD_VBUSDetect` are compiled only for F446, F469, F479, F412, F413, F423: they do not exist in the F407VG build and are not tested; the row below is void, one case checks that `lpm_enable` is ignored): `ActivateLPM` / `DeActivateLPM` (GLPMCFG is not an OTG_FS register: `characterization:`, counted by `hostOtgHsOnlyAccesses`), `ActivateBCD` / `DeActivateBCD` / `BCD_VBUSDetect` (what they write and the state flags; mostly `characterization:`).
- PI4 LL core: `USB_CoreReset` (AHBIDL wait, CSRST self clear, timeouts via poll reads), `USB_CoreInit` (PHY select, `USB_CoreReset`, GCCFG PWRDWN, `Sof_enable`), `USB_SetCurrentMode` (FDMOD / FHMOD, the polling of CMOD), `USB_GetMode`, `USB_SetDevSpeed / GetDevSpeed` (DCFG.DSPD, DSTS.ENUMSPD decode incl. unknown value 0xF), `USB_SetTurnaroundTime` (TRDT for every HCLK frequency band, GUSBCFG), `USB_EnableGlobalInt / DisableGlobalInt`, `USB_DevInit` (every branch: FIFO register zeroing, VBUS sensing, DCFG, endpoint registers reset (EPENA -> EPDIS + SNAK, interrupt flags cleared), DIEPMSK / DOEPMSK, GINTMSK), `USB_DevConnect / DevDisconnect / SetDevAddress / StopDevice`, `USB_ActivateRemoteWakeup / DeActivateRemoteWakeup` (DCTL.RWUSIG).

### PE (`test_hal_pcd_ep.cpp`): endpoints and data movement
`HAL_PCD_EP_Open / Close / Receive / Transmit / GetRxCount / SetStall / ClrStall / Abort / Flush`; LL `USB_ActivateEndpoint, USB_DeactivateEndpoint, USB_ActivateDedicatedEndpoint / DeactivateDedicatedEndpoint (only as far as reachable), USB_EPStartXfer, USB_EPStopXfer, USB_WritePacket, USB_ReadPacket, USB_EPSetStall, USB_EPClearStall, USB_FlushTxFifo, USB_FlushRxFifo, USB_ActivateSetup, USB_EP0_OutStart`.
- PE1 `HAL_PCD_EP_Open / Close`: IN and OUT, EP0 and EP1-3, types (control, bulk, interrupt, iso), the endpoint structure fields (num, is_in, maxpacket, type, tx_fifo_num), DIEPCTL / DOEPCTL (USBAEP, MPSIZ, EPTYP, TXFNUM, SD0PID), DAINTMSK bits, invalid ep address (`EP_ADDR_MSK`, > 3: HAL behaviour on the FS core: `characterization:` or KNOWN_ISSUE as the spec decides), the lock (HAL_BUSY), Close of an enabled endpoint (SNAK + EPDIS, the write of DEACHMSK is counted not a defect), re-open.
- PE2 `HAL_PCD_EP_Receive / GetRxCount / Transmit`: the endpoint structure (xfer_buff, xfer_len, xfer_count, xfer_size), EP0 vs other endpoints (`USB_EPStartXfer` / `USB_EP0StartXfer` branches), DOEPTSIZ / DIEPTSIZ programming (PKTCNT = ceil(len / mps), XFRSIZ, zero length -> PKTCNT 1; EP0 limits), CNAK + EPENA, the DIEPEMPMSK bit (non-periodic IN in slave mode) per RM0090 34.17.5, `HAL_PCD_EP_GetRxCount` of the last packet, DATA PID handling for isochronous (set odd / even frame: `characterization:` unless RM0090 gives the value), len 0, len larger than the FIFO / 64 for EP0.
- PE3 `USB_WritePacket / USB_ReadPacket`: word packing (little endian, odd tails: 1, 2, 3 bytes extra), FIFO window per endpoint, the returned pointer from `USB_ReadPacket` (buffer + len), len 0, unaligned buffer pointers, FIFO overflow reported by the strict model (do not write more than the TxFIFO depth unless `hostOtgStrictFifo(0)` for a deliberate case).
- PE4 stall and flush: `HAL_PCD_EP_SetStall / ClrStall` (IN and OUT, EP0 and others, `HAL_ERROR` for an invalid ep, DIEPCTL.STALL / DOEPCTL.STALL, EP0 OUT restart after SetStall via `USB_EP0_OutStart` (SETUP count 3), CLR: SD0PID, STALL cleared, EPENA preserved), `HAL_PCD_EP_Abort / Flush` (`USB_EPStopXfer`: SNAK + EPDIS and the polling for EPDISD / INEPNE: how the HAL ends and what the model shows; `USB_FlushTxFifo` with the TXFNUM, `USB_FlushRxFifo`, timeouts via poll reads), `USB_ActivateSetup` (DIEPCTL0.MPSIZ = 64, DCTL.CGINAK), `USB_EP0_OutStart` (DOEPTSIZ0 = PKTCNT 1, XFRSIZ 24 / STUPCNT 3, DOEPCTL0 EPENA).

### PQ (`test_hal_pcd_irq.cpp`): interrupt handler and the LL status reads
`HAL_PCD_IRQHandler` (every branch), the static `PCD_WriteEmptyTxFifo` and `PCD_EP_OutXfrComplete_int` / `PCD_EP_OutSetupPacket_int` (reachable only through the handler), LL `USB_ReadInterrupts, USB_ReadDevAllOutEpInterrupt, USB_ReadDevAllInEpInterrupt, USB_ReadDevOutEPInterrupt, USB_ReadDevInEPInterrupt, USB_ClearInterrupts, USB_GetMode`, `HAL_PCD_WKUP_IRQHandler`.
- PQ1 Mode and mismatch: handler does nothing in host mode (set GUSBCFG.FHMOD via poke: CMOD = 1), MMIS cleared.
- PQ2 RXFLVL: status entries popped (one per call; RXFLVL masked and unmasked around it), OUT data packet received (data read into `xfer_buff`, `xfer_count` += BCNT, `xfer_buff` advanced), SETUP data received (8 bytes into `hpcd->Setup`), OUT complete / SETUP complete entries (no data), BCNT 0, a status of another value (global OUT NAK: no action), the XFRC / STUP interrupt that follows when the entry is popped (model decision), `HAL_PCD_DataOutStageCallback` and `HAL_PCD_SetupStageCallback` with the endpoint number, EP0 SETUP restart (`USB_EP0_OutStart`), OUT transfers of several packets (the HAL re-arms the endpoint, `PCD_EP_OutXfrComplete_int` paths: PKTCNT left, short packet, zero length).
- PQ3 OEPINT / IEPINT: DAINT decode (all four endpoints, one call per endpoint bit, lowest first), DOEPINT / DIEPINT bit by bit (XFRC, EPDISD, STUP, OTEPDIS, B2BSTUP if modelled, OUTPKTERR; IN: XFRC, TOC, ITTXFE, INEPNE, EPDISD, TXFE), the clearing writes (rc_w1), the `HAL_PCD_DataInStageCallback` after the last IN packet (including the zero-length status stage of EP0 after SETUP; CORRECTION: the HAL does not call `USB_EP0_OutStart` after an IN XFRC without DMA, NR_PCD_b), the TXFE handling (`PCD_WriteEmptyTxFifo`: packet size, FIFO space check, remaining length, DIEPEMPMSK cleared when done, EP0 and other endpoints, partial writes when the FIFO is short, the `xfer_len` bookkeeping), `HAL_PCD_ISOINIncompleteCallback / ISOOUTIncompleteCallback` branches (IISOIXFR, PXFR_IISOOXFR: counters, the EONUM test is `characterization:`).
- PQ4 Device events: USBRST (the register effects listed by the HAL: flush, interrupt flag clear, DAINTMSK, DOEPMSK / DIEPMSK, DCFG.DAD = 0, `USB_EP0_OutStart`, then the callback order together with ENUMDNE), ENUMDNE (`USB_ActivateSetup`, turnaround time from HCLK, speed fields, `HAL_PCD_ResetCallback`), USBSUSP (`HAL_PCD_SuspendCallback`, the DSTS.SUSPSTS test), WKUPINT (`HAL_PCD_ResumeCallback`, RWUSIG, the PCGCCTL / DCTL changes), SOF (`HAL_PCD_SOFCallback`, flag cleared), SRQINT (`HAL_PCD_ConnectCallback`), OTGINT with SEDET (`HAL_PCD_DisconnectCallback`), DISCINT, the order when several flags are pending at once, `HAL_PCD_WKUP_IRQHandler`, `LPM` branches are not reachable on the FS core (report).
- PQ5 LL status reads: each `USB_Read*` returns exactly the masked / selected bits (GINTSTS & GINTMSK; DAINT >> and << 16 splits; DIEPINT | TXFE from DIEPEMPMSK per RM0090), `USB_ClearInterrupts` writes the argument to GINTSTS (rc_w1).

### PF (`test_hal_pcd_flow.cpp`): end-to-end transfers (HAL + model + host)
Complete control and bulk sequences through the firmware's calls (init, FIFO sizes, start, reset, enumeration done, endpoints open), the host side from `hostOtgHost*`. All expected values come from the USB 2.0 flows in RM0090 34.17.5 and the packet rules of the model (host side of the test: bytes in = bytes out).
- PF1 Control read (GET_DESCRIPTOR style): SETUP -> setup callback -> `HAL_PCD_EP_Transmit` of 18 bytes on EP0 (mps 64 and mps 8: several packets) -> host IN tokens -> data in order -> DataIn callbacks -> status OUT stage (zero length) -> OUT complete callback.
- PF2 Control write: SETUP, OUT data stage with 64 and with 8 byte packets, status IN (zero length transmit), callbacks order.
- PF3 Bulk IN: transfers of 0, 1, 63, 64, 65, 128, 130 bytes on EP1 and EP2 and EP3 (mps 64) with the TxFIFO refilled by TXFE interrupts (FIFO 0x40 words and a short FIFO of 0x10 words: several fills per transfer), ZLP at an exact multiple (the HAL does not add one: the class driver does), NAK of the host token when no transfer is armed, DataIn callback once per transfer.
- PF4 Bulk OUT: transfers of 1, 64, 65 bytes, a NAK while the endpoint is not armed (OTEPDIS flag, nothing reaches the callback), re-arm and receive, `HAL_PCD_EP_GetRxCount`, data integrity over every byte value, two endpoints interleaved.
- PF5 Faults and recovery: USB reset in the middle of a transfer (the host side stops; the HAL re-arms EP0 and the state continues), stall on a bulk endpoint (host sees STALL, `HAL_PCD_EP_ClrStall` ends it), suspend / resume in between, `HAL_PCD_EP_Abort` of an armed IN endpoint, `HAL_PCD_EP_Flush` and a following transfer works, disconnect and reconnect (`HAL_PCD_DevDisconnect` / `DevConnect`: the host gets IGNORED while disconnected).

## Corrections after the T8 review
- FIFO RAM is 320 words (RM0090 34.13): the standard layout of the tests is RX 0x40, TX0 0x20, TX1-3 0x40 each (288 words); the model faults on a layout outside the RAM. `HAL_USB_TIMEOUT` is 2000U in the HAL test builds (CMake), the firmware's 0xF000000 needs minutes per timeout case on the trapping bus.
- DEACHMSK is at 0x83C, DEACHINT at 0x838.
- `GINTSTS.CMOD` and `OTGINT` are not derived by the model (tests poke them); NEEDS REVIEW.
