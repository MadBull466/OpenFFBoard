## SMP: protocol (getSettings, parameter transfers, commands)
- Request bytes by hand derivation: `read1Parameter(553)` no length: `{0x24, 5, adr, 0x80, 0x09, 0x40, 0x02, 0x29, crc16 lo.. }` (see the charter R5.1 and the fake's wire order: ARC low byte first). Compute the expected frame in the test with `FakeSmDevice::crc16arc` or your own bitwise function and compare byte by byte. `read1Parameter` and `set1Parameter` are public; `readParameter` with a length is reached through `getSettings` and `getCpr`. `queueCommand` is public.
- R4: vary `dev.params` (FBD 0..10, FBR, control mode, status 0) and fault flags; check `motorReady()`, `getCpr()`, the error handler entry (`ErrorHandler`, look at how other driver tests read it), the order and bytes of the six requests (`dev.frames()`, `dev.returnAddressRequests()`, `dev.writes()`). - R5.2: decode types 32B / 24B / 16B / status: set `dev.retLen` and use `reg getat` or `read1Parameter` without length; remember that a read without length uses the device's current return format and takes the reply of the SECOND subpacket. ## SMC: motor control, telemetry, commands
- R8.1 `startMotor` writes 2533 = 1: expected request bytes by derivation ([set adr 2533 = 0x09E5: type 2, `0x80 | (2533 >> 8)` = 0x89, 0xE5][32b value 1: 0x00 0x00 0x00 0x01] and the CRC); R8.2 `stopMotor` fast update with 0 then the write of 0; R8.3 `emergencyStop`, `restart` (`dev.restartRequests()`, `hardfault` cleared: observe through `motorReady()` after a faultstop status, `characterization:` for the still-faulted device).
- R9: `dev.params[900]`, `dev.params[901]`; `getVoltage()` 4800 -> 48000 does not wrap (`KNOWN_ISSUE B-SM-3`: evidence -17536); a value that fits (e.g. 1200 counts = 12000 mV) is plain; torque 560 -> 1000, -560 as a 22-bit value `0x3FFFFF - 559`... NOTE: no sign extension of the 22-bit reply (R5.7) but `(int16_t) torque_u` cuts to 16 bits: derive the expected values by hand in a comment and keep negative torque `characterization:` only if the spec leaves it open (the SM docs say 560 counts per ampere; the wire format of a negative 22-bit value is two's complement of 22 bits, the driver's int16 cast of the unextended value gives the same 16 low bits).
