# OpenFFBoard firmware: suspected bugs and open questions

Generated 2026-10-27 at commit `45b1aa47` by `Firmware/Tests/tools/make_bug_report.py` from the tables in `Tests/PROGRESS.md` (the source of truth; regenerated after every phase, so do not edit this file by hand).

Every item comes from the host test suite (`Firmware/Tests`) or from code reading during it. None was fixed: the firmware is read only for the test work. Markers in the "Test" lines:

- `KNOWN_ISSUE`: a test describes the intended behaviour and fails today (the suite stays green). Fixing the bug makes the test report "should have failed": then remove the marker.
- `KNOWN_ISSUE_UB`: the same for undefined behaviour; skipped in sanitizer builds.
- `KNOWN_ISSUE_UB_HIDDEN`: undefined behaviour whose intended result happens to occur on the host; visible only with `--no-skip` in a sanitizer build.
- skipped / crash: the case crashes the test run today and is skipped (`doctest::skip`); run it with `--no-skip` after a fix.
- code reading: no test (not observable through a public interface, or not deterministic).

Counts: 127 suspected firmware bugs, 14 in vendor code (reported, never fixed), 3 not firmware defects, 138 open NEEDS REVIEW questions.

## Look at these first

- **Bug 125** (SerialFFB): Safety: a periodic effect created over the fxm commands has period 0; on the target likely full-scale torque (shipped FFBHIDEXT targets)
- **Bug 124** (SerialFFB): Device stops: damper/inertia over fxm run a null filter; vector-table read, ~2^32-stage loop until a fault or watchdog reset (shipped targets)
- **Bug 40** (FFBHIDMain): Safety: an E-stop press within 1 s of the previous edge is lost
- **Bug 39** (FFBHIDMain): Safety: a new critical error releases an active emergency stop
- **Bug 33** (Axis): Safety: after an E-stop reset the slew limiter starts from the torque before the stop
- **Bug 49** (voltagesense): Safety: brake resistor stuck-on protection disabled for a brake started at tick 0 or after the tick wrap
- **Bug 12** (HidFFB / EffectsCalculator): Crash: an effect changed by Set Effect to damper/friction/inertia keeps null filters
- **Bug 89** (I2CPort): I2C: a PCF8574 waiting for the bus takes over the ADS111X transfer; port blocked until a timeout reset
- **Bug 98** (I2CPort): I2C: a destroyed PCF8574 keeps receiving into its freed buffer
- **Bug 42** (global_callbacks): USB bus suspend never reaches the main class
- **Bug 110** (CANPort2B): CAN: a send with all mailboxes full fails at once instead of waiting
- **Bug 24** (FFBHIDMain): UB whenever a main class is changed (deleting an FFBHIDMain)
- **Bug 41** (flash_helpers): Flash: OTP_Write can reach the OTP lock bytes (permanent)

## Suspected firmware bugs

### Bug 1: EffectsCalculator

- **Where:** `FFBoard/Src/EffectsCalculator.cpp:1048` (`effectsForces`, `std::min<uint8_t>(cmd.adr, MAX_AXIS)`), read at line 1053 `effects_statslast[i].current[axis]`
- **What:** Clamps the axis index to `MAX_AXIS` instead of `MAX_AXIS-1`, then reads `current[MAX_AXIS]` (`std::array<int16_t,2>`) out of bounds. Silent under old libstdc++, aborts under GCC 16 `_GLIBCXX_ASSERTIONS` at -O0
- **Test / evidence:** Existing test `requesting the forces of a not existing axis is rejected` (`cases/test_effects_calculator.cpp:1062`, already `KNOWN_ISSUE_UB`). Message: `/usr/include/c++/16/array:210: ... std::array<short int, 2>::operator[] ... Assertion '__n < this->size()' failed.` -> SIGABRT after 192 of 317 cases. Excluded with `--test-case-exclude`

### Bug 4: EffectsCalculator

- **Where:** see NEEDS REVIEW #2
- **What:** Possible precision/wrap problem of the reconstruction filter after long uptime
- **Test / evidence:** Code reading only; to be demonstrated by a test in Batch 2

### Bug 5: Command execution

- **Where:** `executeCommands` (find with `grep -rn executeCommands Firmware/FFBoard/Src`)
- **What:** Dereferences the command definition before checking it for nullptr. A command with an unknown id terminates the run
- **Test / evidence:** **Confirmed in the source (P0):** `FFBoard/Src/FFBoardMainCommandThread.cpp:99-102`: `cmdDef = handler->getCommandFromId(cmd.cmdId)`, then `validFlags = cmdDef != nullptr`, then `if(cmdDef->flags & ...)` dereferences it unconditionally. Existing test `command with an unknown id is rejected` (`cases/test_command_execution.cpp:186`) stays `skip()`ped (known issue 3)

### Bug 7: ErrorHandler

- **Where:** `ErrorHandler.cpp:130-143` (`getErrors` + `sortErrors`)
- **What:** Empty slots (code 0) sort to the front; `getErrors()` stops at the first empty slot, so after any `clearError`/`clearTemp` it returns an empty list while errors are still stored. **Visible via the `errors` command after every read** (P4: `replyErrors` ends with `clearTemp()` -> `sortErrors()`, so each `errors` read or error-printer pass hides persistent errors from the next read)
- **Test / evidence:** KNOWN_ISSUE "the other errors stay listed after one error is cleared" (`test_error_handler.cpp`) and "a persistent error is still listed by a second errors command" (`test_system_commands.cpp`). Confirmed in source

### Bug 8: ErrorHandler

- **Where:** `ErrorHandler.cpp:118-124` `clearError(ErrorCode)`
- **What:** The slot is emptied before the callbacks, which receive `errors[i]` = an empty Error instead of the cleared one
- **Test / evidence:** KNOWN_ISSUE "clearing by code tells the handlers which error was cleared". Confirmed in source

### Bug 9: ErrorHandler

- **Where:** `ErrorHandler.cpp:66-72` `clearTemp`
- **What:** `break` after the first temporary error: only one is cleared per call; comment says "Clears errors marked as temporary"
- **Test / evidence:** KNOWN_ISSUE "clearTemp removes all temporary errors". Confirmed in source

### Bug 10: EffectsCalculator

- **Where:** `EffectsCalculator.cpp:235` (square wave)
- **What:** Raw phase (0.01 deg) added as milliseconds instead of `phase*period/36000` like sine/triangle; 90 deg on a 1000 ms period shifts by 984 ms instead of 250 ms
- **Test / evidence:** KNOWN_ISSUE "square phase is a fraction of the period like for the other periodic effects". Confirmed in source

### Bug 11: HidFFB

### Bug 12: HidFFB / EffectsCalculator

- **Where:** `HidFFB.cpp:301-305` + `:423`, crash at `EffectsCalculator.cpp:416/425/433`
- **What:** **Crash:** a running effect without filters (e.g. sine) changed by Set Effect to damper/friction/inertia keeps null filters (423 skips `set_filters` for running effects); the next force calculation dereferences nullptr (UB: SIGSEGV on the host; on the target `Biquad::process` is non-virtual and address 0 aliases boot flash, so it may output garbage torque or corrupt memory instead of faulting)
- **Test / evidence:** KNOWN_ISSUE "a running effect changed to a damper by set effect has damper filters" (stops at `REQUIRE(filter[0] != nullptr)`); crash confirmed by the author with a temporary probe

### Bug 13: CommandHandler

- **Where:** `CommandHandler.cpp:533-561`
- **What:** The override placeholder from `overrideCommandFlags_INT` lacks `CMDFLAG_EXTOVERRIDE`, so `registerCommand_INT` treats the id as "already present": the real command is never registered (placeholder keeps `cmd == nullptr`; `getCommandFromName` would compare nullptr with a string = UB)
- **Test / evidence:** KNOWN_ISSUE "a command registered after a flag override gets its name and the masked flags". Confirmed in source

### Bug 14: Filters

- **Where:** `Filters.cpp:44/86` + `:102`, reachable via `EffectsCalculator.cpp:868-872`
- **What:** Clip allows Fc = 0.5 (comment: "Must be lower than 0.5"); with CMSIS-DSP `arm_cos_f32(PI/2)` is exactly 0, K = inf, NaN coefficients, NaN output. DSP off: finite but a double pole on the unit circle. `checkFilterCoeff` maps a stored freq of 0 to Fc = 0.5
- **Test / evidence:** KNOWN_ISSUE in the DSP build only "lowpass at the highest allowed frequency 0.5 ...". Target result may differ (FMA)

### Bug 15: Filters (latent)
