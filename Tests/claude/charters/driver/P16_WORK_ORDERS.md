## RMS: identity, construction, life cycle
- R1.1 identity (`info` names and class ids from `ClassIDs.h`, `getInfo()`, `hasIntegratedEncoder`, `getEncoder` returns the driver, `getEncoderType` absolute, `getCpr` 36000), R1.2 `MotorDriver::all_drivers` contains ids 11 and 12 once, `Create` builds a working object (look at the P14 / P15 setup tests for the chooser pattern), R1.3 `isCreatable` over create and destroy for both instances, instance 2 stays creatable while instance 1 exists, R1.4 defaults without flash.
- R2.1-R2.5: filter ids, mask and buffer (the fake CAN filter table holds the `buffer` / FIFO of each filter: check its fields in `HostTarget.h`), filter released at destruction, change of id replaces it (via the `canid` command), port speed preset raised to 3 only when lower (set the preset before construction through the fake CAN port as other tests do), silent mode off, restore before filter (seed the flash with another id).
- R10: destruction removes the filter and sends `{0xA1, 0...}` then `{0x80, 0...}` (frames recorded after `delete`: use `rmd.reset()` then inspect the frame log; the fixture's `Deleter` runs `delete`), `inUse` flag, `canport.getPortUsers()` before / after (R10.2 `KNOWN_ISSUE B-RMD-1`: the first failing assertion is the user count after destruction), create / destroy / create, two instances at once (buffers 0 and 1, their own ids, the frames of one do not reach the other: use `peer1.sendReply` and `peer2.sendReply` and observe through `temp` / `vbus`).

## RMF: frames sent, thread cycle
- R3: every frame standard id `0x140 + nodeId`, DLC 8, unused bytes 0 (fake already fails on violations: still assert the first frame explicitly). `setTorque` is public: t = 0, 1, 100, -100, 32767, -32768 with the SP example bytes in HD comments. `turn` table with `maxtorque` 1000: p = 0, 32767, -32767, 16384, 1, -1 expected 0, 1000, -1000, 500, 0, 0 (HD: `trunc(p / 32767.0f * 1000)`; 16384 / 32767 * 1000 = 500.0153 -> 500; derive each in a comment). Preconditions: `startMotor` needs `lastErrors == 0` (default), `turn` needs `available` (`reachAvailable`). R3.4 `startMotor` sends one zero torque frame and with errors set (peer reply 0x9A through `requestpos 1` mode or `peer.sendReply(0x9A)` with `peer.setErrors`) sends nothing. R3.5, R3.6 (`emergencyStop`), R3.7 `requestConstantReports` is public: bytes for interval 0, 1, 300, enable false. R3.8 `characterization:` no 0x77 ever sent in a full session.
- R4: thread timing against a silent motor (`peer.setSilent(true)`) and against a replying motor; 0xB5 not repeated while available; falling silent clears `available` at the end of the next cycle; `requestpos 1`: 0x9A every cycle, no 0xB6; switching modes sends the disable `{0xB6, 0x92, 0, 0, 0, 0, 0, 0}` once and the next cycle re-enables; same value twice sends nothing; destruction stops the cyclic requests (advance time after `reset()` and see no new frame). Constants are `characterization:`, frame contents plain. Use `clearTxFrames()` and `txFramesCmd` for counting. Remember `runFor` runs the peers: a peer that replies makes the driver available.

## RMR: receive path, position, status
- Replies are produced by the peer (`setTemperature`, `setIq`, `setSpeed`, `setShaftAngle`, `setVoltage`, `setErrors`, `setModel`, `setMultiTurn`, `setSingleTurn`) and sent with `peer.sendReply(cmd)` or by letting the driver request them. Observe through the commands `temp`, `curr`, `vbus`, `errors`, `model`, `getPos`.
- R5.1 foreign frames (id 0x242 for node 1, `peer2.sendReply` while only instance 1 exists, wrong node id fault `setFaultNode`) change nothing and do not set `available`; R5.2 0xA1 values incl. negative iq; R5.3 0x9A temperature, voltage 0x01E5 = 485, errors 0x0004; R5.4 `KNOWN_ISSUE B-RMD-7` (-10 degC reads 246); R5.5 model string; R5.6 unknown command byte (0x60, 0x9C: `setFaultCmdByte`) only sets `available`; R5.7 `ErrorStatus` union: `KNOWN_ISSUE B-RMD-4` (assert the SP bit positions through the public bit field; the first failing assertion is the `overpower` field at 0x0040).
- R6: 0x92 values 36000, -1, 0, 1 234 567 (HD: float tolerance one count; note `lastPos` is a float of degrees: values above 2^24 counts are not exact, assert with a tolerance of 1 count only where the HD comment shows the float arithmetic), `setPos`, request mode refresh (10 / 11 ms boundary around `angleUpdateMs`: `getPos` sends 0x92 only when `HAL_GetTick() - lastAngleUpdate > 10`), passive mode never sends 0x92 from `getPos`, R6.4 0xA1 in passive mode leaves the position, R6.5 `KNOWN_ISSUE B-RMD-6` (speed 500 dps, 10 ms after the previous 0xA1, request mode: intended 2.5 degrees = 250 counts; the first failing assertion is the position), R6.6 `characterization:` for the 0x94 formula (lastPos 720 degrees then single turn 10000 (100.00 deg)), R6.7 informational only if testable without stale data.
- R7: error flag -> `stopMotor` frames (A1 0 then 0x80), `errors` value, `motorReady` false, `startMotor` refused until a 0x9A reply with 0 flags; 0x9A reply with 0 flags sends nothing; R7.4 `characterization:` passive mode never requests 0x9A over several cycles; R7.5.

## RMC: commands and persistence
- R8: `canid` get / set (1..32 changes frame ids, filter and reply: send a frame after the change and check the peer with the new node id `peer.setNodeId` answers), R8.2 `KNOWN_ISSUE B-RMD-2` (0 not accepted; 256 not truncated to 0: two tests, first failing assertion is the returned status or the stored id), R8.3 33..255 clamped to 32 `characterization:`, `maxtorque` get / set and use by `turn`, R8.5 `KNOWN_ISSUE B-RMD-3` (40000 rejected), R8.6 `KNOWN_ISSUE_UB` (`turn(0x7fff)` with 40000: float 40000.0 does not fit int16), `curr` / `temp` / `vbus` / `errors` / `model` / `requestpos` get, SET on GET-only commands -> `ERR`, an unknown command id through `command()` -> `NOT_FOUND` (build a `ParsedCommand` with an id outside the enum; do NOT use `executeCommands` path that dereferences null).
- R9: `saveFlash()` words (HD: word 1 = `(nodeId - 1) & 0x1F | activerequests << 6`; word 2 = `maxTorque & 0x7FFF`; word 3 = `posOffset % 36000` as `uint16_t`) for id 1 / 32, request mode on / off, `maxtorque` 1 / 1000 / 32767, both instances at their own addresses (R9.5); read the words back with the host flash API like the ODrive flash tests. `restoreFlash()` / constructor restore (seed the words, construct, check commands and filter), bits 5 and 7-15 ignored, a missing address keeps the default; offsets through `setPos` then `saveFlash` then a new instance: R9.3 `KNOWN_ISSUE B-RMD-5` (35000 comes back -30536: first failing assertion is the restored position), R9.4 -1 and -35999 round trip (plain, HD).
- Reaching the offset: `setPos(p)` sets `posOffset = (int32)(lastPos * 100) - p`; set a known `lastPos` first with a 0x92 reply (peer multi turn angle) so the offset is deterministic.
