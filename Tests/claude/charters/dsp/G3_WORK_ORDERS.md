Lessons from G1/G2 that every writer applies (all of them found real defects or gaps): (1) never put two calls of a pseudo random generator in one expression; (2) at least one strided sweep over the whole input range of the type against a double DEF (V41, V42 and V50 were found by full-range sweeps, ARM's patterns miss isolated bad inputs); for q7 (and q15 where cheap) make the sweep EXHAUSTIVE over the single-sample domain; (3) a test name claims only what its assertions check (a guard check of a buffer only the test writes is not a library guard check); (4) UB in vendor code (left shifts of negative values, signed overflow, negation of INT_MIN): `KNOWN_ISSUE_UB` / `KNOWN_ISSUE_UB_HIDDEN` and report with file:line, first failing assertion = the defect; (5) the DEF is evaluated in double inside the test, never with a library function; for saturating q functions saturate the DEF the way DOC says (derive the intermediate scaling in a comment: e.g. q31 mean accumulates in q63? read DOC and source for accumulator width and the right shift, and test the overflow boundary, not just typical data); (6) one-sided error properties (truncation: error in (-n, 0]) are asserted one-sided, not as a symmetric bound; (7) a bound must be derived in a comment and must not be looser than needed (mutants of 1e-5 relative size should die in f32; a one-LSB constant change should die in q types).
Host-vs-target (C6): the host runs the portable C path (no ARM_MATH_DSP intrinsics, no MVE); say so where it matters; flag results that could differ with FMA contraction, float summation order (the unrolled loop sums in groups of 4: mean / var / std / power differ in the last bits between host and target: derive the bound from the summation, e.g. n * eps * sum|x|).
Also: `arm_norm_64_to_32u` and `arm_div_int64_to_int32` (inline helpers of `dsp/utils.h`, ARM ids "Fast Maths Q63": `test_norm_64_to_32u`, `test_div_int64_to_int32`, desc.txt:1948-1965, `Testing/Source/Tests/FastMathQ63.cpp`) belong to SQ31 (lead decision L7): C1 from ARM's pattern, plus DEF checks incl. 0, powers of two, INT64_MIN / INT64_MAX and the divisor edge cases that DOC allows.
