G5-specific requirements:
- **DEF (C3):** double / `__int128` / exact integer model of the documented operation. Convolution `y[n] = sum a[k] b[n-k]`, output length `srcALen + srcBLen - 1`; correlation `r[n] = sum a[k+n] b[k]` over the lag range with the documented output ordering (read the DOC: the output order and length of `arm_correlate_*` differ from conv); partial convolution `(firstIndex, numPoints)` window of the full result, incl. the documented `ARM_MATH_ARGUMENT_ERROR` when the window is out of range (quote the DOC and test the status and that nothing is written on error where DOC says so); LMS `y = w.x`, `e = d - y`, `w += mu e x` (and norm-LMS with the energy normalisation: derive the q formats and shifts in comments); lattice structures from the DOC equations; sparse FIR with the `pTapDelay` positions and the circular buffer; Levinson-Durbin with a hand-derived small case (Yule-Walker n = 1, 2, 3) and ARM's reference patterns.
- **Argument roles:** conv and correlate have swapped-argument conventions (srcA longer than srcB is NOT required by the ARM API: the function swaps internally) and the fast / opt variants need scratch buffers whose size is given in the DOC (`pScratch1` / `pScratch2`: size formulas): use EXACTLY the DOC size from a tight heap allocation. Test both srcALen >= srcBLen and srcALen < srcBLen, lengths 1 .. 9 and the unroll tails (ARM unrolls by 4 / 2; q15 SIMD paths read pairs: odd lengths).
- **Output guards and state:** every output in a `dsp::GuardedBuffer` (guard intact, nothing past `outLen` touched) AND, for each function with a state buffer (lms, lattices, sparse FIR) or scratch buffers (opt / fast_opt variants), a tight exact-size heap allocation WITHOUT slack, because `GuardedBuffer` keeps its guard words in the same allocation and ASan cannot see small overruns (G4 review finding). Keep both.
- **State continuity** for the stateful functions (lms, lms_norm, lattices, sparse FIR): one long block equals several consecutive blocks (sizes 1, 2, 3, 4, 5, 7, ...); two instances independent; re-init resets the state; LMS: the coefficient vector after N samples equals the DEF.
- **Inits:** instance fields hold the arguments, the state buffer is zeroed (poison it first), documented argument errors tested with the return code (quote the DOC). Call every init unconditionally into a local and fold the status into the result (a short-circuiting `status && init(...)` crashes the whole run on failure: G4 review finding); `REQUIRE` the stored fields before running a kernel on the instance.
- **Saturation / wrap (lead rules, from G4):** where the DOC contradicts itself (e.g. "wraps around rather than clip" and "saturated to 1.31" in the same function) or the code differs from the DOC for a result that is in range, do NOT assert one reading as a plain test: a test of the library's behaviour is `characterization: ...` + NEEDS REVIEW in the header (quote both DOC sentences); a KNOWN_ISSUE only where the DOC is unambiguous and the code contradicts it. Never assert a value that comes from UB (signed overflow, left shift of negative, out-of-range float-to-int) as a plain test: `KNOWN_ISSUE_UB(_HIDDEN)` or untested + NEEDS REVIEW. Check the DOC input-range preconditions of the fast variants (e.g. "input must be scaled down by N bits") and stay inside them.
- **Exact models derived from the library** (fast variants whose DOC says "truncated" but the code rounds) must be named `characterization:`; the primary oracle is the DEF with a derived bound.
- **Sweeps:** q7 / q15 one- and two-tap convolutions can be swept exhaustively against the exact model; wider types: strided full-range sweep. Block sizes 0: do not test where the kernel would read out of bounds, list as NEEDS REVIEW (`numTaps`/`blockSize` 0 and `numStages` 0 style items go on the list).
- **Lessons from G1-G4 every writer applies:** never two PRNG calls in one expression; a test name claims only what its assertions check (list exactly the sizes run); floor / truncation error asserted one-sided with a strict bound (floor error is strictly > -1); tolerances derived in a comment (no magic numbers); f16 code only in `_f16.cpp` files; no bitwise comparison between different block partitions (use the derived bound; bitwise only for identical partitions or exact data); host-vs-target notes (C6): `__int128` needs a 64-bit host, FMA contraction, excess precision.
- **UB hunting:** run every case under UBSan with `--no-skip` (one process per case if needed); report UB with file:line; cases that hit UB in the unrolled path get `KNOWN_ISSUE_UB_HIDDEN` with ONE id per defect (ids `B-D<WO>-<n>`; the lead renumbers).
